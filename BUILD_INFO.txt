PATCH 2026-11-17 — "database is locked" on save (POST /add_client)
------------------------------------------------------------------
Problem : SQLite's rollback journal (forced on PythonAnywhere, whose /home is
          NFS) lets an open READER block a save's COMMIT. A save landing during
          a long page render waited the full 15 s busy_timeout, then returned
          500 with "database is locked" (traceback failed at db.session.commit).
Fix     : app/services/db_busy.py + install_busy_retry(app) in app/__init__.py
          Every mutating route (268 handlers) now waits up to 30 s for the lock
          and retries; if it is still busy the user is told "nothing was saved,
          press Save again" instead of getting a 500. Non-lock DB errors are
          never retried; imports/backups/restores/exports/mail are excluded.
Verified: reader holding the lock 20 s -> save SUCCEEDS (was 500 at 15.0 s)
          lock never released          -> friendly message, no 500
          genuine DB error            -> still reported (correct)
Tuning  : AMS_BUSY_RETRY_BUDGET_SECONDS (default 30), AMS_BUSY_RETRY=0 disables.
Notes   : Keep SQLITE_JOURNAL_MODE=DELETE on PythonAnywhere. Do NOT enable WAL
          there (needs shared memory NFS cannot provide).
See     : PATCH-DB-LOCKED-FIX.md
